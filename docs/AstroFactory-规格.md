> 一段话交给 AI 即可开工。数值来自 Factorio Wiki，但**不必照抄**，适配边界见 §3。

---

## 1. 项目

复刻《异星工厂》前期（到 Automation 2）的 Minecraft 模组。

**七条必须还原的体验**：手搓开局 / 烧煤物流 / 机械臂也烧煤 / 两台采矿机对脸自转 / 传送带免费 / 红瓶能手搓 / 矿脉会枯竭。

| 项 | 值 |
|---|---|
| mod_id | `astrofactory`，包 `com.xiaoyi.astrofactory` |
| 目标 | MC **26.3** + NeoForge **26.3.0.113** |
| 构建 | Gradle 9.2.1 + moddev，Java 25 |
| 工程 | `E:\AI Work\XiaoYi\MC Mod` |
| 命令 | `set GRADLE_USER_HOME=%CD%\.gradle-home` 后 `gradlew.bat build --offline` |

**26.3 陷阱**（违反必失败）：

1. `ResourceLocation` → **`Identifier`**，旧类不存在
2. `BlockEntityType.Builder` 已删 → `new BlockEntityType<>(supplier, Set<Block>)`
3. BlockEntity 存档用 **`ValueInput` / `ValueOutput`**，不是 `CompoundTag`
4. GUI 是 **extract 式**（`GuiGraphicsExtractor`），不是 `render(GuiGraphics)`
5. `ContainerData.get()` 必须实时读真实数据
6. `runData` 不可用

**铁律**：API 签名先查 `docs/api-26.3-notes.md` 或反编译 jar，查不到就说查不到，禁止编造。

## 3. 红线 / 灰区

**红线（不许改）**：燃烧期吃煤、燃烧臂偷燃料、对脸自转可行、传送带免费、背压传导到矿机、矿脉枯竭、组装机电动、红瓶可手搓、"造好组装机才发现没电"的顺序。

**灰区（可调，需说明理由）**：传送带 0.08~0.12｜矿脉 200~500｜矿田间距 40~64｜煤续航 ≤15 个/熔炼｜配方 ±30%｜教程步数可合并。

**判断标准**：调完后玩家仍会经历「烧煤紧张 → 发现要发电 → 扩张找矿」，就是对的。

**与幸福工厂的边界**：只借鉴垂直运输、沉浸感、基地；不借鉴 3D 曲线布线、传送带直插机器、资源无限。

## 5. 系统规格

### 5.1 多方块（第一个做）

所有机器真实占格：采矿机/熔炉 2×2，组装机/科研台 3×3，锅炉 2×3，蒸汽机 3×5。

- **master + dummy**：只放 1 个 master（带 BlockEntity）+ 若干 dummy（无 BE）
- 放置前**整体预检**，任一格不可放就整体拒绝
- 破坏任意一格 → 整体拆除、掉 1 个物品
- master 碰撞箱完整 N×N，dummy 空碰撞、全透明
- 右键 dummy 转发到 master 的 GUI
- **区块重载自修复**：master 在 dummy 缺 → 补；master 缺 dummy 在 → 清
- 抽基类 `MultiBlockMachineBlock`，所有机器继承

### 5.2 传送带

1 个方块，`FACING` 决定直行/转弯，`SLOPE`（flat/up/down）决定斜坡。

- 物品持 `progress`(0~1) + `lane`(0/1) + `yOffset`
- 每 tick `progress += 0.094`，到 1.0 尝试移交，下游满则**卡在 1.0**（背压）
- **背压必须一路传导到采矿机**
- 渲染做视锥 + 距离剔除（>64 格不渲染），同步用脏标记批量

**斜坡（借鉴铁轨斜放）**：放置时看前方高差自动判定 up/down。物品 y **线性插值**（up: `0.1875 + progress×1.0`），**禁止曲线**。坡度固定 1 格，连续放多个即可升多格。上下游必须同向，否则堆积。不要照抄 `RailShape` 的 10 态。

### 5.3 机械臂

燃烧臂（26 tick，1 煤 58 次，**会从搬运的煤里偷燃料**）与电动臂（17 tick，用电）并存。

**硬规则**：除采矿机出矿口，所有机器进出料必须经机械臂，禁止自动吸附。

### 5.4 机器

- 采矿机 2×2，覆盖下方 2×2，产物可直推传送带，也可进另一台采矿机的燃料槽（**对脸自转**）
- 石熔炉 1 进 1 出 + 燃料
- 组装机 4 进 1 出，电力驱动，配方 JSON 无序匹配
- 科研台 1 科技包槽，进度存玩家 attachment
- 组装机/科研台断电 → 停机，GUI 显示「无电力」

### 5.5 动力

三阶段：燃烧（采矿/熔炉/燃烧臂）→ 蒸汽 → 电力（组装机/科研台/电动臂）。

**统一抽象** `PowerSource`（`Fuel` / `Steam` / `Electric` 三实现），机器用组合持有。

蒸汽电力做最小版：锅炉烧煤产蒸汽 → 蒸汽机发电 → 电线杆 5 格供电。**不做**压力、温度、损耗、电压等级。

### 5.6 矿脉

真实方块带储量（300/块），`richness` 四态切贴图（**不要用 BER**）。矿田 7×7~15×15，铁:铜:煤:石 = 3:2:2:2。**出生点 64 格内保底 4 片**，用 `SavedData` 保证幂等。

### 5.7 新手教程

玩家 attachment 存 step，右上角**可折叠任务卡** + 世界**线框高亮**。18 步，从"放第一台采矿机"到"搭出自动产线"。

**关键**：第 13-15 步先让玩家放下组装机、发现不转，才告诉他需要发电。这个"先撞墙再给梯子"的顺序不许改。

不强制弹窗、不锁操作、不用粒子。开局给 1 本手册（JSON 数据，不要每条写 Screen 类）。

## 6. 工程约束

- 双端安全：渲染只在 `client` 包，BlockEntity 里不出现 `Minecraft`
- 注册集中在 `ModRegistry`
- 配方/科技走 JSON，Java 只放默认值
- tag 兼容 `#c:`
- 存档兼容：读不到用默认值，不许崩
- 性能：空带不 tick，渲染剔除，机器用活跃列表
- 资源完整：blockstate/model/贴图/中英 lang
- 贴图用 PIL 脚本生成，2×2/3×3 要有"一体机"观感

## 8. 验收

一个切片算完成，必须**同时**满足：

1. `build --offline` 通过，产出 jar
2. `runClient --offline` 能进游戏，创造栏能拿到方块，放置不崩
3. 手动实测通过并给出步骤

关键切片：矿脉（4 片矿田 + 采空变贫矿）｜传送带（连续移动 + 背压停满）｜斜坡（3 个 up 升 3 格）｜机械臂（偷燃料 + 没燃料不动）｜多方块（整体拒绝/整体拆/无幽灵）｜电力（断电线停机）｜自给煤矿（对脸运转 10 分钟）｜教程（18 步走完）
